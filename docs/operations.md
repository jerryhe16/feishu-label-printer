# 使用、校准与故障处理

在源表点击一次按钮，等待队列出现一条任务并处理。不要因网络延迟连续点击；每次点击都是新任务。

| 状态/现象 | 含义和处理 |
| --- | --- |
| 待打印 | 电脑离线、休眠、未登录、后台未启动，或正在排队 |
| 处理中 | 本机已接收；不要重复提交 |
| 已发送 | Windows接收，检查打印机缺纸、碳带、连接和实物 |
| 排版失败 | 查看处理结果；料号为空、过长、二维码URL不一致或文字放不下 |
| 需核对 | 无法确定是否已发送/出纸；先检查Windows打印队列与实物，再决定是否新建任务 |
| 点击后无队列记录 | 检查工作流是否启用、按钮绑定、字段映射及飞书自动化运行记录 |
| 所有任务都不动 | 查看runtime/bridge.log、CLI登录状态和用户权限 |

## 校准

只修改 `config.local.json` 中对应profile的 `vertical_offset_mm`。正数下移，负数上移；300dpi时1mm约12点。修改后停止旧程序、等待退出，再resume和启动。程序不会修改打印机全局校准参数，也不会改变另一个profile的偏移。

30×20mm布局可能无法容纳长编号的Code 128。程序要求条码最窄模块至少2点；样机QR每模块3点，保留四模块静区。禁止压缩或裁掉二维码来强行适配。更长内容需要重新设计或更大标签，不能仅修改ZPL纸张大小。

## 试印与预览

使用 `preview` 生成PNG和ZPL，检查文字完整性后，在飞书点击一条新的样例任务。实物扫码结果才是最终验证；软件解码成功不能保证特定扫描器、碳带和纸张的组合可用。

当前项目不自动监控物理出纸。`已发送`不是`已打印`。

## 重印与恢复

需要重印时点击源表按钮，生成新队列记录。不要把旧任务改回待打印；本地数据库会识别旧任务并回写历史结果，避免重复出纸。

程序在发给Windows之前记录本地去重状态。若进程在临界时刻中断，宁可留为需核对，也不自动重发。云端结果写回失败会在下次轮询恢复，不再次发送到打印机。

保留 `runtime/jobs.sqlite3`。删除数据库会丢失去重记录；更换电脑前，应停止旧电脑程序、核对所有未结束任务，并使用单一消费者。此实现不提供多电脑负载均衡或严格的跨系统exactly-once保证。

## 凭证与权限

不在配置内保存app secret或用户token。CLI登录过期时，在同一Windows用户下重新运行 `lark-cli auth login --domain base`。租户管理员限制、资源ACL不足等问题需要在飞书侧处理。二维码没有绕过文档权限。
